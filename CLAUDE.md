# CLAUDE.md — konteks proyek Racikin

Racikin ("Racik ide jadi cuan") = PWA co-founder AI untuk usaha F&B kecil di Indonesia. Pemilik: mirwanma. Live: https://racikin.vercel.app (deploy otomatis dari `main` lewat Vercel). Detail fitur ada di `README.md`, rencana & riwayat fase di `docs/PRD.md`.

## Cara kerja dengan pemilik proyek
- Bahasa: **Indonesia santai** (pengguna & pemilik). Teks UI juga santai ala anak muda, **tanpa emoji** (ikon garis dari `js/icons.js` → `icon(nama, ukuran)`).
- Alur: satu fitur = satu branch `claude/<nama>` dari `main` terbaru → commit → push → **PR** (pemilik me-review & merge sendiri). Setelah merge, lanjut fitur berikutnya dari `main` terbaru.
- Fitur yang tidak dipakai semua usaha (dapur, pesan meja, foto) harus **opsional** (default nonaktif, toggle oleh pemilik/manajer).
- Jangan simpan secret/password di repo. Secret Supabase diisi pemilik di dashboard.

## Arsitektur
- **Frontend tanpa build**: vanilla ES modules, router hash (`js/app.js`), event delegation `data-action` (click) / `data-change` / `data-form`. View = objek `{ render(s), after(root), actions, changes, forms }` yang mengembalikan template string.
- **State**: satu objek di `localStorage` (`racikin:v1`, `js/store.js`). `store.set(patch)` → render ulang. `DEFAULT` di store.js = daftar semua key.
- **Service worker** `sw.js`: naikkan `VERSION` (saat ini `racikin-v49`) di setiap rilis dan tambahkan file baru ke `SHELL`.
- **Desain "papan warung"**: kuning marigold `#FFC531`, ink `#1B1916`, paper `#F6EFDC`; font Archivo + IBM Plex Mono; token warna di `:root` + mode gelap. Layar ≥ 900px: rail navigasi kiri, halaman di `COLS` (app.js) dua kolom, Kasir dua panel.
- **Peran** (`js/cloud.js`): `owner`, `manajer`, `kasir` (hanya Kasir/Pelanggan/Stok; boleh menulis `bills`), `dapur` (hanya layar dapur). Rute dibatasi di `app.js` (`KASIR_ROUTES`, `DAPUR_ROUTES`), dan server juga membatasi.

## Supabase (project `racikin`, ref `ujdxslztjcufidhqpmcd`, ap-southeast-1)
- **Sinkron**: satu dokumen JSON per usaha (`user_data`, kolom `rev`), dibaca/ditulis lewat RPC `doc_get` / `doc_save` (optimistic locking) + **3-way merge** di klien (`js/merge.js`; field penghitung seperti `stok`, `stempel`, `delta` digabung sebagai selisih). Setelah merge, Kas & rekap kasir dihitung ulang dari order (`reconcile` di `js/pos.js`). Kasir tidak menerima & tidak bisa menulis bagian keuangan (`doc_kasir_hidden` / `doc_kasir_writable` di SQL).
- **Admin platform**: tabel `platform_admins` (diisi manual pemilik via SQL Editor) + fungsi `is_platform_admin` / `admin_merchants` / `admin_merchant_detail` / `admin_harian` untuk dashboard `#/admin` (read-only, `js/admin.js`). Akun admin otomatis masuk **mode admin** (`isAdminMode` di `js/views/admin.js`, `body[data-admin]`): menu Ringkasan / Merchant / Pertumbuhan / Akun, rute usaha dialihkan (`ADMIN_ROUTES` di app.js), bisa pindah ke app usaha dari Akun. Desain admin pakai token `--a-*` (gelap default lewat `prefers-color-scheme`, ada versi terang) dan kelas `a-*` di app.css. Jangan kirim kas/laba/data pelanggan merchant lewat fungsi admin.
- **Tabel lain**: `ai_usage`, `stamp_cards`, `team_members`, `team_invites`, `push_subscriptions`, `kitchen_tickets` (Realtime), `public_menu` (termasuk grup varian), `table_orders` (Realtime), Storage bucket `menu-foto`. Akses lewat RLS `team_role(owner_id)`; fungsi publik (anon) hanya untuk kartu stempel & pesan meja, dan harga **serta promo** dihitung di server (`meja_items`, `meja_promo`, `cek_promo_meja`; aturan promo di `public_menu.data.promoAturan` dari `aturanPromoMeja` di `js/promo.js`, harus tetap sama dengan `pilihPromo`).
- **Migrasi** di `supabase/migrations/` (urut timestamp). Terapkan lewat MCP Supabase `apply_migration`, lalu simpan file yang sama di repo.
- **Edge Functions** (`supabase/functions/`): `racikin-ai` (Gemini teks + foto untuk task ber-`gambar: true` seperti `parse_menu`/`parse_bahan`, fallback Claude; prompt & schema di `tasks.ts`), `racikin-push` (Web Push buatan sendiri + pg_cron 15 menit, `verify_jwt=false`; jenis pengingat di `notif.ts`: konten, stok, ajak, rekap, pajak, utang, kasbon, gaji, jadwal — logika tagihan diporting dari js/*.js, jadi kalau aturan pajak/gaji/utang berubah, ubah juga di sini), `racikin-foto` (edit foto Gemini, kuota terpisah). Deploy lewat MCP `deploy_edge_function` dengan **semua file** fungsi.
- Secret yang dipakai: `GEMINI_API_KEY` (wajib). Opsional: `GEMINI_MODEL`, `GEMINI_IMAGE_MODEL`, `RACIKIN_LIMIT_*`, `RACIKIN_FOTO_PER_DAY`, `RACIKIN_ALLOWED_ORIGIN`.
- **Catatan**: model gambar Gemini butuh **billing aktif** di Google AI Studio (paket gratis → 429). Auth: "Confirm email" dimatikan dan SMTP Resend belum dipasang.

## Paket Gratis & Pro
Server yang menentukan paket (`paket_info` / `paket_saya`, tabel `langganan` & `platform_setting`): Pro berbayar → masa transisi (akun lama s/d 20 Feb 2027) → masa coba 14 hari → Gratis. Fitur mana yang Gratis / Pro, kuota AI, harga, masa coba & transisi diatur admin di `#/admin?tab=paket` (`platform_setting.fitur`, `ai_gratis`, `ai_pro`; `admin_set_paket`). Server mengunci lewat `fitur_boleh(owner, fitur)` & `ai_limit` (tim: `team_role`/`create_invite`/`join_team`, meja: `meja_dari_token`, foto: `consume_ai_quota_task`). Di app: `bolehFitur(id)` (`js/paket.js`, tanpa akun = boleh dicoba) + `kunciPro(fitur)` (`js/views/paket.js`). Fitur baru yang bisa diatur: tambahkan ke `FITUR` (paket.js) **dan** `paket_fitur_ids()` (SQL), lalu kunci di server kalau datanya lewat server.

## Kasir: open bill & pembayaran campuran
Open bill opsional (`posSetting.openBill`, `js/bill.js`, data `bills`): ronde memotong stok saat dikirim, uang masuk Kas hanya saat bill dilunasi (`buatOrder(..., { stok: false, bill })`); bayar sebagian lewat `keranjangPilih` + `bayarSebagian`, juga `gabungBill` / `pindahMeja`. Pembayaran campuran: `order.pembayaran` + `metode: "campur"`; semua hitungan per metode harus lewat `porsiMetode` (pos.js) / porsi di shift.js.
Kasbon opsional (`posSetting.kasbon`, `js/kasbon.js`, data `kasbon`, `#/kasbon`): metode `kasbon` (bisa + DP tunai) tidak masuk Kas di `kasPatch`, utang `o-<orderId>`; pelunasan → Kas `kasbon-<tgl>-<metode>` kategori "Pelunasan kasbon" (dihitung ulang di `reconcile`, jadi kasir yang menerima bayar tidak perlu menulis Kas). Invarian: Kas kasir per hari = omzet − bagian kasbon; laba rugi menghitung kasbon saat order, pajak saat dilunasi.
Utang ke supplier (`js/utang.js`, data `utangSupplier`, tab Utang di `#/belanja`): `catatBelanja(..., { utang: { tempo } })` membuat nota tanpa Kas; pembayaran → Kas `utang-<bayarId>` (`ref: "utang"`, kategori proporsional isi nota). Karyawan & absen (`js/absen.js`, `#/karyawan`, data `karyawan` / `absen` / `absenSetting`): karyawan tanpa akun, posisi custom (`absenSetting.posisi`), absen efektif = catatan tersimpan, kalau kosong dari shift kasir (`absenHari`); impor file mesin absen lewat `kenaliTabel` + `olahAbsen` + `simpanImpor`, Excel dibaca SheetJS vendor yang dimuat saat dibutuhkan (bukan di `SHELL`). Gaji (`js/gaji.js`, tab Gaji, data `gajian` / `kasbonKaryawan`, `karyawan.gaji`): bayar → Kas `gaji-<id>` Gaji kotor + `gaji-<id>-kasbon` masuk "Potong kasbon karyawan"; pinjam → `kbk-<id>` keluar "Kasbon karyawan"; kategori pinjam/potong tidak dihitung laba rugi (`KAT_PIUTANG` di laporan.js). Lembur (`lemburPeriode`, `karyawan.gaji.lembur`), THR (`hitungThr`, data `thr`, `absenSetting.hariRaya`). Setelan gaji & lembur cuma pemilik, atau manajer kalau `absenSetting.manajerAturGaji` (`bolehAturGaji`); server mengunci lewat `kunci_gaji` di `doc_save`. Jadwal shift (`js/jadwal.js`, tab Jadwal + `#/jadwal` untuk kasir, data `jadwal` = `{ shift, hari, akun }`, sengaja tidak disembunyikan dari kasir): `telat` & `lemburPeriode` memakai `jamShift` kalau dijadwalkan; `jadwal.akun` diperbarui `sinkronAkun` tiap simpan karyawan / jadwal. Ekspor: `tabelJadwal` / `aoaJadwal` → Excel (SheetJS lewat `js/xlsx.js` `muatXlsx`) & lembar cetak `.jadwal-cetak` (`body[data-cetak="jadwal"]`, @page landscape dipasang sementara).
Transaksi Kas ber-`ref` utang/kasbon/pajak tidak dihapus dari halaman Kas (tag `TERKAIT` di `views/kas.js`).

## Tahap usaha
`profile.tahap` = `ide` (default, alur dari ide) atau `jalan` (usaha sudah berjalan: langkah Beranda & halaman Bisnis beda, lihat `js/tahap.js`). Pindahan data usaha lama: `#/impor?jenis=menu|bahan` (teks/foto) + saldo kas awal (`kasAwal`, `js/impor.js`) + impor penjualan lama `#/impor-jual` (`js/imporjual.js`, rekap ber-`imporId`, Kas `ref: "impor"`). Cek kesehatan usaha: `#/sehat` (`js/sehat.js`). Panduan perizinan: `#/izin` (`js/izin.js`, isi panduan bertanggal `DICEK`, perbarui kalau aturan berubah). Pajak UMKM: `#/pajak` (`js/pajak.js`, PPh Final 0,5% dari omzet Kas, bebas Rp500jt untuk orang pribadi, catat bayar → Kas kategori Pajak, data `pajak` disembunyikan dari kasir; `DICEK` juga). Fitur baru sebaiknya cocok untuk dua-duanya.

## Data contoh
`js/dummy.js` (tombol di Setelan / onboarding), profil tahap `jalan`: 15 menu (sebagian dengan varian: level pedas, topping, ukuran (Jumbo 1,5× porsi), tingkat manis (ada "Tanpa gula" yang menghilangkan gula)), 3 promo (happy hour, es teh weekend, voucher TAHGUY5), 25 bahan, ±2.600 order 60 hari yang **tumbuh ±3×** (opsi `tumbuh`, `skala`), belanja ikut naik (stok diisi ulang dari pemakaian sekitar hari itu, nggak pernah minus) + frozen food 10 hari terakhir tempo (utang supplier), Kas, 35+ pelanggan (opsi `pelangganAda` memakai identitas & token kartu lama), 5 supplier, shift 30 hari atas nama tim, 8 meja, 5 karyawan (`tambahTim`: jadwal shift s/d 2 minggu ke depan, absen, gaji mingguan/bulanan lewat `bayarGaji`, kasbon karyawan; Rina/Dodi/Sari terhubung ke akun tim). Semua angka harus tetap konsisten: Kas = rekap kasir per hari, stok = total `stokLog`, stempel = total `stempelLog`, Kas Gaji = total gajian, Kas utang = yang sudah dibayar (dicek di `tests/e2e/dummy.js`). Data hari ini hanya sampai jam sekarang. Batas dokumen di server 2 MB (ukuran JSONB sebelum kompres): ±70 order/hari selama 30 hari sudah mendekati batas.
